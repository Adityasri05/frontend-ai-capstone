# Real Captures vs. AI Substitutes

This document highlights three examples where actual project screenshots (real captures) were deliberately selected over AI-generated mockups, outlining what value is preserved by prioritizing authenticity.

---

## Example 1: HIREVIUM Recruiter Dashboard
- **Visual**: Recruiter candidate management matrix and AI scoring log.
- **Why Real?**:
  Hiring managers need to see that the React component logic actually aligns columns, handles text overflows, and renders dynamic stats cleanly. A real screenshot showcases actual front-end CSS, form controls, and DOM structures.
- **What AI Would Have Lost**:
  An AI mockup would generate a visually perfect but completely fake dashboard with gibberish text or impossible layouts that don't match actual React component code. This makes the engineering work look fabricated, instantly disqualifying the developer's credibility.

---

## Example 2: INDRA AI Citation Drawer
- **Visual**: PDF intelligence highlight list and citation source tags.
- **Why Real?**:
  It proves that the developer has built a functioning citation system that maps LLM outputs back to database chunks. A real screenshot shows the exact document view frame, source link tags, and coordinate Highlights.
- **What AI Would Have Lost**:
  AI generation cannot capture the precise relationship between grounded answers and database citation cards. It would produce generic stock panels that fail to prove the developer understands Retrieval-Augmented Generation (RAG) UI patterns.

---

## Example 3: StackScout Vendor Comparison Matrix
- **Visual**: Live crawl logs and procurement matrix comparisons.
- **Why Real?**:
  Proves the interface handles asynchronous log streaming and crawls structured pricing columns from vendor sites.
- **What AI Would Have Lost**:
  AI-generated diagrams would output generic charts or glowing robot icons that fail to prove the existence of an autonomous agent compare utility, reducing the portfolio to abstract slides.
